If everyone sends as fast as they can, the network jams, and then nobody gets through. Congestion control is how TCP avoids that. This page explains the rule it follows.

## Start with a motorway

Cars are fine until too many enter at once. Then the road fills, everything slows, and nobody gets far. A ramp signal that lets cars on one at a time keeps the road moving. TCP is its own ramp signal.

## What congestion is

Routers keep a queue of packets waiting to go out. When packets arrive faster than they can leave, the queue fills up. A full queue drops new packets. This is *congestion*.

TCP cannot see inside the network. It sees only its own packets: whether they get through and how long they take. A lost packet is a sign of congestion.

## The congestion window

TCP keeps a limit called the *congestion window*. It is the amount of data the sender may have in flight at once. The window changes as TCP learns how much the network can take.

- **Slow start.** The window starts small and about doubles every round trip. It is called slow because it starts small, but it grows fast.
- **Congestion avoidance.** Once the window reaches a set point, it grows by only about one segment each round trip.
- **After a loss.** TCP cuts the window. In a version called Reno, a loss noticed through repeated acknowledgements halves it, and then it grows again.

:::example Worked example
This is a simplified version, and the table was generated by a script. The window is counted in segments. It starts at 1, and slow start ends when it reaches 16.

| Round trip | Window (segments) | Phase |
|---|---|---|
| 0 | 1 | slow start |
| 1 | 2 | slow start |
| 2 | 4 | slow start |
| 3 | 8 | slow start |
| 4 | 16 | slow start ends |
| 5 | 17 | congestion avoidance |
| 6 | 18 | congestion avoidance |
| 7 | 19 | congestion avoidance |
| 8 | 20 | congestion avoidance |

Say a loss is noticed when the window is 20, because the receiver keeps repeating the same acknowledgement. A Reno sender then cuts the window to 10 and grows again from there. If the sender's timer runs out instead, the window drops back to 1 segment and slow start begins again.
:::

Many modern systems start with 10 segments, not 1. The idea is the same.

## Why the sawtooth

Because the window grows slowly and drops fast, a graph of it looks like the teeth of a saw. Each drop is the sender backing off when it senses a jam, so many senders can share one link.

## Common mistakes

- **"Congestion control and flow control are the same."** Flow control protects the receiver from being overwhelmed. Congestion control protects the network.
- **"Slow start is slow."** It starts small, but doubling is fast growth.

## Check yourself

:::check
Q: In slow start, the window is 8 segments. What is it after the next round trip?
A: 16 segments, because it doubles.
Q: A loss is noticed through repeated acknowledgements at a window of 20. What does a Reno sender do?
A: It cuts the window to 10 and then grows again.
Q: What does TCP treat as a sign of congestion?
A: A lost packet.
:::

:::deeper
**Other versions.** Reno is a classic design. Linux uses a version called CUBIC by default, and newer designs such as BBR estimate the link speed instead of waiting for loss.

**Queue management.** Routers can also help by marking or dropping packets early, before the queue is full.
:::
